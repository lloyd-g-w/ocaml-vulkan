# ocaml-vulkan — design contract

This document is the binding contract between the code generator, the
hand-written runtime, the tests and the examples. **If you change an interface
described here, update this file in the same commit.**

## 1. Goals

* Complete OCaml bindings to the Vulkan API (core 1.0 → 1.4 plus every
  extension in `registry/vk.xml`, excluding the `vulkansc` API and
  `VK_ENABLE_BETA_EXTENSIONS`/provisional-platform-only types where noted).
* Generated from the Khronos XML registry (`registry/vk.xml`, version pinned in
  `registry/VERSION`) by `gen/gen.py` (Python 3, stdlib only). Generated code is
  **committed** so users only need `ctypes` + `ctypes-foreign` to build.
* No C stubs, no Vulkan headers at build time. `libvulkan.so.1` (or the
  platform equivalent) is loaded at runtime with `Dl.dlopen`; every entry point
  is fetched through `vkGetInstanceProcAddr` / `vkGetDeviceProcAddr` (volk
  style), so extensions work without linking.
* Two layers, both generated:
  1. a faithful **raw layer** (`Vk.Fn`): ctypes types + one OCaml function per
     Vulkan command with the C signature;
  2. an **ergonomic layer** (`Vk.*`): struct constructors with labelled
     arguments, lists instead of count+pointer pairs, exceptions for
     `VkResult` errors, two-call enumeration helpers.
* 64-bit platforms only (x86_64 / aarch64, Linux first; macOS/Windows should
  work but are untested).

## 2. Repository layout

```
dune-project            (lang dune 3.x) package "vulkan"
vulkan.opam             generated by dune from dune-project
registry/vk.xml         vendored Khronos registry (see registry/VERSION)
gen/gen.py              generator entry point (python3 gen/gen.py)
gen/vkgen/*.py          generator package (parse / naming / emit modules)
gen/layout_check.py     emits a C program printing sizeof/offsetof of all structs
lib/dune                (library (name vk) (public_name vulkan)) with
                        (include_subdirs unqualified)
lib/vk.ml               hand-written main module: includes everything below
lib/vk_base.ml          hand-written runtime support (views, keep-alive, loader)
lib/generated/*.ml      generator output — DO NOT EDIT BY HAND
test/                   alcotest tests (run headless on lavapipe)
test/layout/*.txt       golden struct layouts produced with real C headers
examples/               vkinfo, compute, offscreen triangle
scripts/regen.sh        regenerate lib/generated from registry/vk.xml
```

Library name is `vk` (main module `Vk`), opam/public name `vulkan`.
Users write `Vk.create_instance`, `Vk.ImageLayout.general`, etc. Do **not**
`open Vk` in user code: some modules (`Format`, `Result`, `Buffer`, `Queue`,
`Semaphore`, `Event`) shadow Stdlib modules on purpose (names follow Vulkan).

Generated files (all under `lib/generated/`):

| file | contents |
|------|----------|
| `vk_consts.ml` | API constants, `header_version`, extension names & spec versions |
| `vk_enums.ml` | one module per enum / flag type, `Result`, `exception Error`, `check` |
| `vk_handles.ml` | one module per handle type |
| `vk_types_NN.ml` | structs, unions and function-pointer types, topologically sorted, chunked (~120 structs per file) |
| `vk_layout.ml` | `all : (string * int * (string * int) list) list` — (C struct name, ctypes sizeof, [(C member name, ctypes offset)]) for every struct/union |
| `vk_fn.ml` | module `Fn`: raw commands (`Foreign.funptr_opt` refs) and loaders |
| `vk_api.ml` | ergonomic wrappers for commands |

`lib/vk.ml`:

```ocaml
include Vk_base.Public      (* next, keep-alive helpers, version helpers, string helpers, Loader *)
include Vk_consts
include Vk_enums
include Vk_handles
include Vk_types_01 ... include Vk_types_NN
module Fn = Vk_fn
include Vk_api
module Layout = Vk_layout
```

## 3. Naming rules (implemented in `gen/vkgen/naming.py`)

* Types: drop the `Vk` prefix, keep CamelCase: `VkPhysicalDeviceProperties2`
  → module `PhysicalDeviceProperties2`; `VkImageUsageFlags` → module
  `ImageUsageFlags`; handle `VkCommandBuffer` → module `CommandBuffer`.
* Flag types: the `FlagBits` enum and the `Flags` typedef are merged into a
  **single** module named after the `Flags` typedef
  (`VkImageUsageFlagBits` + `VkImageUsageFlags` → `ImageUsageFlags`).
  `VkAccessFlagBits2` + `VkAccessFlags2` → `AccessFlags2`. A `Flags` typedef
  with no bits enum still gets a module (empty flags).
* Enum values: strip the type-derived prefix, drop `_BIT`, lowercase:
  `VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL` → `ImageLayout.color_attachment_optimal`;
  `VK_IMAGE_USAGE_COLOR_ATTACHMENT_BIT` → `ImageUsageFlags.color_attachment`;
  `VK_ACCESS_2_SHADER_READ_BIT_KHR` → `AccessFlags2.shader_read_khr`;
  `VK_SAMPLE_COUNT_4_BIT` → `SampleCountFlags._4`; `VK_IMAGE_TYPE_2D` →
  `ImageType._2d` (identifiers that would start with a digit get a `_` prefix).
  Vendor suffixes are kept when they are part of the value name and not part of
  the type name. Never emit `*_MAX_ENUM`. Emit aliases as extra values.
  If the prefix-stripping yields an OCaml keyword, append `_`
  (e.g. `VK_STENCIL_OP_..._TYPE` never happens, but `begin_`, `end_`, `type_`, `object_`, `method_`, `val_`, `or_`, `and_`, `to_`, `of_`, `in_`, `new_`, `open_`, `private_` etc.).
* Struct members and command parameters: camelCase → snake_case, keeping the
  Hungarian prefixes in the **raw** field names (`pNext` → `p_next`,
  `ppEnabledExtensionNames` → `pp_enabled_extension_names`, `sType` → `s_type`,
  `pfnUserCallback` → `pfn_user_callback`). Digits keep their position:
  `maxImageDimension2D` → `max_image_dimension_2d`, `srcAccessMask3` → `src_access_mask_3`.
  Ergonomic argument labels drop the `p`/`pp`/`pfn` prefix
  (`~application_name`, `~enabled_extension_names`, `~user_callback`).
* Commands: `vkCmdDrawIndexed` → `cmd_draw_indexed` (same name in `Vk.Fn` and
  `Vk`). `vkGetPhysicalDeviceProperties2KHR` → `get_physical_device_properties_2_khr`.
* Constants: `VK_MAX_PHYSICAL_DEVICE_NAME_SIZE` → `Vk.max_physical_device_name_size`,
  `VK_WHOLE_SIZE` → `Vk.whole_size` (= `-1`, i.e. all bits set as uint64),
  `VK_KHR_SWAPCHAIN_EXTENSION_NAME` → `Vk.Ext.khr_swapchain = "VK_KHR_swapchain"`,
  `VK_KHR_SWAPCHAIN_SPEC_VERSION` → `Vk.Ext.khr_swapchain_spec_version`.
* Vendor tags come from `<tags>` in vk.xml; never hard-code the list.

## 4. Scalar representation (`Vk_base`)

All C integers are exposed as OCaml `int` through ctypes views
(`Vk_base.uint8/uint16/uint32/uint64/int8/int16/int32/int64/size_t/
 device_size/device_address`). `uint64` uses two's-complement conversion so
`-1` ⇔ `0xFFFF_FFFF_FFFF_FFFF`; bits 62–63 of unsigned 64-bit values are not
representable as positive ints (Vulkan does not use them; documented limitation).
`VkBool32` ⇔ OCaml `bool` (`Vk_base.bool32`). `float` ⇔ `float`, `double` ⇔ `float`.
`char*` members are `char ptr` (never the `string` view, which can't hold NULL);
`char name[N]` members are `char carray` with a generated `get_<name>` helper
returning `string` (stops at NUL).
Platform/opaque foreign types (`Display*`, `xcb_connection_t*`, `HWND`,
`wl_surface*`, `CAMetalLayer`, `AHardwareBuffer`, `IOSurfaceRef`, `MTLDevice_id`,
`NvSciSync*`, `OHNativeWindow`, `_screen_context`…) are `unit ptr`;
`Window`/`xcb_window_t`/`zx_handle_t`/`GgpFrameToken`/`DWORD`/`HANDLE`… are
`uint64`/`uint32`/`unit ptr` as declared in the `basetype`/platform headers
(generator keeps a small explicit table; every basetype must resolve or the
generator fails loudly).

## 5. Enums and flags (`vk_enums.ml`)

Each enum/flag module is an instance of a functor from `Vk_base`:

```ocaml
module ImageLayout : sig
  type t = private int
  val t : t Ctypes.typ                (* int32 view for enums, uint32/uint64 for flags *)
  val of_int : int -> t
  val to_int : t -> int
  val undefined : t
  val general : t
  ...
  val to_string : t -> string         (* "VK_IMAGE_LAYOUT_GENERAL" or "ImageLayout(1234)" *)
  val pp : Format.formatter -> t -> unit
  val equal : t -> t -> bool
  val compare : t -> t -> int
end
```

Flag modules additionally provide `empty`, `( lor )`, `( land )`, `union`,
`inter`, `diff`, `mem : t -> t -> bool` (`mem flags bit`), `of_list`,
`to_list`, and `to_string` prints `"VK_A_BIT | VK_B_BIT"`. 64-bit flag types
(`bitwidth="64"`) use the `uint64` view.

`Result` is an enum module; immediately after it:

```ocaml
exception Error of Result.t          (* registered printer: "Vk.Error(VK_ERROR_DEVICE_LOST)" *)
val check : Result.t -> unit         (* raise Error when to_int r < 0 *)
```

`StructureType` (VkStructureType) is generated like any enum.

## 6. Handles (`vk_handles.ml`)

```ocaml
module type HANDLE = sig
  type t
  val t : t Ctypes.typ
  val null : t
  val is_null : t -> bool
  val equal : t -> t -> bool
  val to_int64 : t -> int64
  val of_int64 : int64 -> t
  val to_nativeint : t -> nativeint     (* interop with tsdl's Sdl.Vulkan *)
  val of_nativeint : nativeint -> t
  val to_string : t -> string           (* "0x7f..." *)
end
module Instance : HANDLE      (* dispatchable: view over (ptr void) *)
module Buffer : HANDLE        (* non-dispatchable: view over uint64_t *)
```

Handle aliases (`VkDescriptorUpdateTemplateKHR` → `VkDescriptorUpdateTemplate`)
become `module DescriptorUpdateTemplateKHR = DescriptorUpdateTemplate`.

## 7. Structs and unions (`vk_types_NN.ml`)

```ocaml
module InstanceCreateInfo : sig
  type t
  val t : t Ctypes.structure Ctypes.typ
  val s_type : (StructureType.t, t Ctypes.structure) Ctypes.field
  val p_next : (unit Ctypes.ptr, t Ctypes.structure) Ctypes.field
  val flags : (InstanceCreateFlags.t, t Ctypes.structure) Ctypes.field
  val p_application_info : (ApplicationInfo.t Ctypes.structure Ctypes.ptr, t Ctypes.structure) Ctypes.field
  val enabled_layer_count : (int, t Ctypes.structure) Ctypes.field
  val pp_enabled_layer_names : (char Ctypes.ptr Ctypes.ptr, t Ctypes.structure) Ctypes.field
  ...
  val structure_type : StructureType.t option   (* Some StructureType.instance_create_info *)
  val make :
    ?next:Vk_base.next ->
    ?flags:InstanceCreateFlags.t ->
    ?application_info:ApplicationInfo.t Ctypes.structure ->
    ?enabled_layer_names:string list ->
    ?enabled_extension_names:string list ->
    unit -> t Ctypes.structure
end
```

Rules for `make` (all arguments optional, every field written explicitly,
`sType` set automatically, memory zero-filled by `Ctypes.make`):

| C member | `make` argument |
|----------|-----------------|
| `sType` | none (set from `structure_type`) |
| `void* pNext` | `?next:Vk_base.next` — `Vk.next s` wraps any structure, keeps it alive |
| integers, `size_t`, `VkDeviceSize` | `int`, default `0` |
| `float`/`double` | `float`, default `0.` |
| `VkBool32` | `bool`, default `false` |
| enum / flags | module type, default `of_int 0` |
| handle | handle module type, default `null` |
| struct by value | `X.t Ctypes.structure` (copied) |
| union by value | `X.t Ctypes.union` |
| `const T* p` (single, no `len`) for struct/union T | `?x:T.t Ctypes.structure` → stores `addr`, kept alive |
| `const char* p` (`len="null-terminated"`) | `?x:string` |
| `T* p` + `uint32_t xCount` (`len="xCount"`) | `?xs:elem list` → allocates a `CArray`, sets count = length (or the longest of several lists sharing one count, or an explicit `?x_count:int` override when every array sharing the count is independently optional — see §10's expansion of this row), keeps array **and** original structures alive |
| `const char* const* pp` + count | `?xs:string list` |
| `const void* pData` + `size_t dataSize` (`len="dataSize"`) | `?data:string` (raw bytes) — sets size |
| `const uint32_t* pCode` + `size_t codeSize` (`len="codeSize / 4"`) | `?code:string` (SPIR-V bytes; copied into a 4-byte aligned buffer, sets code_size) |
| other `len` expressions | raw pointer argument (`?p_x:... Ctypes.ptr`) and explicit count |
| `T x[N]` numeric fixed array | `?x:int list` / `float list` (padded with zeros, error if longer than N) |
| `char x[N]` | `?x:string` |
| bitfield members (`:24`, `:8`) | merged into one raw field `<first>_bits` of the declared width; `make` takes each bitfield separately and packs LSB-first |
| function pointer (`PFN_*`) | the OCaml closure type of the PFN module (see §8), wrapped with `Foreign.funptr_opt`; keeps the closure alive |
| `T* p` non-const output pointer with no `len` | `?p_x:T ptr` raw (rarely used in make) |

Structs marked `returnedonly="true"` get a `make` that only accepts `?next`
(sets `sType`/`pNext`, everything else zero) — this keeps compile time down.

Keep-alive mechanism: `make` creates `keep : Obj.t list ref`, allocates with
`Ctypes.make ~finalise:(fun _ -> ignore (Sys.opaque_identity !keep)) t`, and
pushes every OCaml-side allocation (CArrays, strings, nested structures,
closures) into `keep`. The GC finaliser closure keeps them reachable exactly as
long as the struct's memory is. Users who fill pointers with `setf` themselves
are responsible for lifetimes (documented in README).

Unions: `module ClearValue` has `type t`, `t : t Ctypes.union Ctypes.typ`,
fields, and one constructor per member (`ClearValue.color : ClearColorValue.t
Ctypes.union -> t Ctypes.union`, `ClearColorValue.float32 : float list -> t
Ctypes.union`, …).

Struct aliases (`VkPhysicalDeviceFeatures2KHR` → `VkPhysicalDeviceFeatures2`)
become `module PhysicalDeviceFeatures2KHR = PhysicalDeviceFeatures2`.

Every struct module is also registered in `vk_layout.ml`.

## 8. Function pointer types

The 11 `funcpointer` types become modules named after the C typedef with the
`PFN_vk` prefix replaced by `Pfn`: `PFN_vkDebugUtilsMessengerCallbackEXT` →
`Vk.PfnDebugUtilsMessengerCallbackEXT`:

```ocaml
module PfnDebugUtilsMessengerCallbackEXT : sig
  type fn = DebugUtilsMessageSeverityFlagsEXT.t -> DebugUtilsMessageTypeFlagsEXT.t ->
            DebugUtilsMessengerCallbackDataEXT.t Ctypes.structure Ctypes.ptr -> unit Ctypes.ptr -> bool
  val t : fn Ctypes.static_funptr Ctypes.typ  (* raw *)
  val opt : fn option Ctypes.typ              (* Foreign.funptr_opt ~runtime_lock:true, used in struct fields *)
end
```

`PFN_vkVoidFunction` is `unit ptr`. Function pointers are ordered in the
same topological sort as structs (they reference structs and are referenced
by structs).

## 9. Commands (`vk_fn.ml`, module `Vk.Fn`)

For every command (including aliases) the generator emits:

```ocaml
let create_instance_ref : (InstanceCreateInfo.t structure ptr -> AllocationCallbacks.t structure ptr -> Instance.t ptr -> Result.t) option ref = ref None
let create_instance a b c = match !create_instance_ref with
  | Some f -> f a b c
  | None -> Vk_base.not_loaded "vkCreateInstance"    (* raises Vk_base.Not_loaded *)
```

Parameter typing = struct member typing (§4/§5/§6): handles are handle views,
enums are enum views, integers are `int`, `const char*` **parameters** are the
ctypes `string` view, pointers are `ptr X`, `void*` is `unit ptr`.

Loaders (also in `Vk.Fn`, re-exported via `Vk.Loader`):

* `Vk.Loader.load : ?library:string -> unit -> unit` — dlopen (default
  `libvulkan.so.1` on Linux, `libvulkan.1.dylib` on macOS, `vulkan-1.dll` on
  Windows; overridable via `?library` or `$OCAML_VULKAN_LIBRARY`), resolve
  `vkGetInstanceProcAddr`, load all global commands. Idempotent; global
  commands call it implicitly on first use.
* `Vk.Loader.load_instance : Instance.t -> unit` — populate **all**
  instance- and device-level commands through `vkGetInstanceProcAddr`.
  Missing entry points stay `None`.
* `Vk.Loader.load_device : Device.t -> unit` — optional, overrides device-level
  commands with `vkGetDeviceProcAddr` pointers (skips loader trampolines; only
  valid for single-device apps).
* `Vk.Loader.get_instance_proc_addr : Instance.t -> string -> unit ptr` and
  `get_device_proc_addr`.

Command level classification: global if the first parameter is not a handle;
device-level if the first parameter's handle type is `VkDevice` or has
`VkDevice` in its `parent` chain (`VkQueue`, `VkCommandBuffer`); otherwise
instance-level. `vkGetInstanceProcAddr` and `vkGetDeviceProcAddr` are
special-cased.

Split of responsibilities between hand-written and generated code:

* `Vk_base.Loader` (hand-written): `load ?library ()` does the `Dl.dlopen`,
  resolves the real `vkGetInstanceProcAddr` symbol with `Foreign.foreign`,
  then calls `!global_hook ()`; exposes `get_instance_proc_addr`,
  `get_device_proc_addr` (raw `unit ptr` results), `ensure : unit -> unit`
  (cheap, idempotent) and the hook refs `global_hook`, `instance_hook :
  (unit ptr -> unit) ref`, `device_hook`.
* `Vk_fn` (generated): defines `load_global ()`, `load_instance inst`,
  `load_device dev` that fill every command ref via the proc-addr functions and
  registers them into the `Vk_base.Loader` hooks at module initialisation.
  Global command stubs call `Vk_base.Loader.ensure ()` before dispatching.
* `lib/vk.ml` exposes `module Loader` combining both.

## 10. Ergonomic wrappers (`vk_api.ml`, top-level `Vk.*`)

Generated from the command signatures with these rules (fall back to a plain
alias of the raw function when a shape is not recognised — never omit a command):

* `pAllocator` parameters become `?allocator:AllocationCallbacks.t structure`.
* A trailing non-const pointer output parameter (`VkInstance* pInstance`,
  `VkMemoryRequirements* pMemoryRequirements`, `void** ppData`, `uint32_t* pImageIndex`) is
  allocated by the wrapper and returned. Output structs that have `sType`
  are instead taken **as an argument** (so callers can chain `pNext`), and the
  wrapper returns `unit`/result.
* `VkResult` returns: raise `Vk.Error` when negative. If the command's
  `successcodes` contains anything other than `VK_SUCCESS`, the wrapper also
  returns the `Result.t` (as the first component of a tuple when there is an
  output value: `acquire_next_image_khr : ... -> Result.t * int`).
* Two-call enumeration (`uint32_t* pCount` + `T* pItems` with `len="pCount"`):
  wrapper returns `T list` (structs: `T.t structure list`, with `sType` filled
  when applicable; handles/ints/enums: their OCaml type). Handles
  `VK_INCOMPLETE` by retrying.
* An output array whose `len` is **not** an in/out `pCount` (so not the
  two-call idiom above) but derives from another input instead becomes a
  returned OCaml list, allocated and filled by the wrapper:
  * `len` equal to a plain (by value) input count that also sizes an input
    array — `vkCreateGraphicsPipelines`/`vkCreateComputePipelines`/
    `vkCreateRayTracingPipelinesKHR`/`vkCreateRayTracingPipelinesNV`/
    `vkCreateShadersEXT`/`vkCreateSharedSwapchainsKHR`/... (`pPipelines` len
    = `createInfoCount`, the same count that sizes `pCreateInfos`): the
    output list is exactly as long as the input list sharing its count, e.g.
    `create_graphics_pipelines device cache infos : Result.t * Pipeline.t
    list` (the result is kept because `VK_PIPELINE_COMPILE_REQUIRED_EXT` is a
    success code — per the `VkResult` rule below).
  * `len` of the form `param->field` — `vkAllocateCommandBuffers`
    (`pCommandBuffers` len = `pAllocateInfo->commandBufferCount`) and
    `vkAllocateDescriptorSets` (`pDescriptorSets` len =
    `pAllocateInfo->descriptorSetCount`): the count is read from the input
    struct (`Ctypes.getf info X.command_buffer_count`), e.g.
    `allocate_command_buffers device info : CommandBuffer.t list` (no extra
    success codes here, so no `Result.t`).
  * Anything else with a `len` that isn't recognised by one of the shapes
    above (`vkGetQueryPoolResults`'s byte-sized `pData`, the two-call
    `vkGetImageSparseMemoryRequirements`, ...) is unaffected and keeps its
    existing wrapper shape; `Vk.Fn` always keeps the raw pointer-based
    signature regardless.
* Input `count + const T*` pairs become `elem list` arguments (temporary
  CArrays live for the duration of the call). Structs → `T.t structure list`,
  handles/enums/ints/floats → their OCaml types, `const char* const*` → `string list`.
  The same rule applies one level down, inside `X.make` (§7): when a count
  member is shared by more than one array member (e.g.
  `VkSubpassDescription.colorAttachmentCount` sizes both `pColorAttachments`
  and the optional, parallel `pResolveAttachments`; `VkWriteDescriptorSet.
  descriptorCount` sizes whichever one of `pImageInfo`/`pBufferInfo`/
  `pTexelBufferView` applies to `descriptorType`), the count is derived from
  the **longest** list actually supplied (not an arbitrary single member),
  and supplying two of those lists with different non-zero lengths is an
  `Invalid_argument`. When *every* array sharing a count is independently
  optional (registry `optional="true"` on the pointer, e.g.
  `VkDescriptorSetLayoutBinding.descriptorCount`/`pImmutableSamplers`, where
  a binding can declare any `descriptorCount` with no immutable samplers at
  all), `make` also accepts the count as a plain, independent
  `?xxx_count:int` argument that overrides the derived length.
* Single `const T* pInfo` input struct → `T.t structure` (passed by `addr`).
* `const void*` + size pairs stay raw (`unit ptr` + `int`).
* `Vk.create_instance` additionally calls `Loader.load_instance` on success.
  `Vk.create_device` does **not** call `load_device` (multi-device safety).
* Names are the same as in `Vk.Fn`.

Examples of intended usage:

```ocaml
let app = Vk.ApplicationInfo.make ~application_name:"demo" ~api_version:Vk.api_version_1_3 () in
let ci = Vk.InstanceCreateInfo.make ~application_info:app ~enabled_extension_names:["VK_KHR_surface"] () in
let instance = Vk.create_instance ci in
let pds = Vk.enumerate_physical_devices instance in
let props = Vk.get_physical_device_properties (List.hd pds) in
print_endline (Vk.PhysicalDeviceProperties.get_device_name props);
let qf = Vk.get_physical_device_queue_family_properties pd in
let device = Vk.create_device pd (Vk.DeviceCreateInfo.make ~queue_create_infos:[Vk.DeviceQueueCreateInfo.make ~queue_family_index:0 ~queue_priorities:[1.0] ()] ()) in
Vk.cmd_bind_vertex_buffers cb 0 [vbuf] [0];
Vk.queue_submit queue [Vk.SubmitInfo.make ~command_buffers:[cb] ()] fence;
Vk.destroy_device device ()   (* ?allocator omitted *)
```

## 12. Tests (`test/`), all headless on lavapipe (`VK_ICD_FILENAMES` may be
used to force `lvp_icd.json`)

* `test_enums.ml`: to_string/of_int round trips, flags ops, Result printing.
* `test_layout.ml`: `Vk.Layout.all` vs `test/layout/x86_64-linux-gnu.txt` (golden file
  generated by `gen/layout_check.py` + real headers; the test skips with a
  message if the golden file for the platform is missing).
* `test_structs.ml`: `make` sets `sType`, counts, arrays; keep-alive survives
  `Gc.full_major`.
* `test_instance.ml`: create instance, enumerate devices/extensions/layers,
  properties, queue families, create device, allocate buffer + memory, map.
* `test_compute.ml`: compute pipeline doubles an array of ints (SPIR-V embedded).
* `test_graphics.ml`: offscreen render pass draws a triangle into an image,
  copies to a host buffer, checks pixel colours.

## 13. Generator invariants

* `python3 gen/gen.py` must be deterministic (sorted iteration) and fail with
  a clear error on any unknown C type rather than silently emitting `ptr void`.
* Only `api="vulkan"` (or unspecified) items are generated; `vulkansc`-only
  items are skipped.
* Deprecated/promoted aliases are emitted (`module X_KHR = X`).
* Output files start with `(* Generated by gen/gen.py from registry/vk.xml — do not edit *)`
  and disable noisy warnings: `[@@@warning "-32-33-34-37-39-60"]`.
* The generator is the single source of truth: never hand-edit `lib/generated`.
